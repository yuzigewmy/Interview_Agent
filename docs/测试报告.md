# Interview Agent v0.2.1 测试报告

日期：2026-07-24  
环境：Windows x64、.NET SDK 8.0.423、Release 配置

## 结论

v0.2.1 修复了 v0.2 的模型首字性能回归。除原有文本/RAG、协议解析、密钥存储和真实 BGE 推理外，自定义模型、按需短期上下文、问答记录、DOCX 导出和音频设备刷新选择均已验证。所选模型服务与火山引擎的真实线上联调仍需要用户自己的已开通账号。

## v0.2.1 性能回归分析

脱敏诊断日志显示，同一环境中升级前 40 次请求的首字延迟中位数为 500 ms、P90 为 733 ms且没有超过 4.5 秒；升级后的 10 次请求中位数升至 3,897 ms、P90 为 7,128 ms，其中 5 次超过 4.5 秒。对应请求的本地检索仍约为 10–16 ms，因此瓶颈不在 RAG。

代码对比确认 v0.1 会向 DeepSeek V4 发送 `thinking: disabled`，而通用模型改造时移除了该提供商专用字段。DeepSeek V4 默认开启思考，应用又只展示正式 `content`，因此不可见推理直接推迟了首字。同时，v0.2 对独立问题也发送历史上下文，并可能让模型流处理与本地兜底竞争 UI 调度。

修复后：

- DeepSeek 官方端点及明确标记为 DeepSeek 的提供商恢复非思考、`temperature: 0.2` 的上一版请求合同。
- 其他 OpenAI 兼容提供商不接收 DeepSeek 专用字段。
- 历史上下文只在明显追问时携带最近 2 轮。
- 模型协调在后台执行，本地兜底先于模型任务启动，并提前到 4.0 秒。
- 确定性回归测试证明，即使模型枚举器同步阻塞 300 ms，本地兜底自身仍在 150 ms 测试预算内启动。

## 五秒目标

自动化测试证明：

- 云端首字先到时不显示本地兜底。
- 云端无首字时在配置的 4.0 秒边界显示知识库答案。
- 总请求 30 秒超时，新问题取消旧问题。

修复版没有擅自使用用户 API Key 发起计费请求，因此最终公网首字时间仍需用户在真实账号下复测。即使第三方服务变慢，只要知识库有命中，4.0 秒本地路径仍会先输出；网络完全不可用时则保留本地答案并显示安全错误。
