# Interview Agent v0.3.0 测试报告

日期：2026-07-24  
环境：Windows x64、.NET SDK 8.0.423、Release 配置

## 结论

v0.3.0 在保留 v0.2.1 低首字延迟路径的基础上增加桌面悬浮球、音量波浪和双消息气泡。悬浮窗口真实创建与渲染、设置迁移、跨屏布局、音量归一化以及流式 UI 更新合并均已验证。所选模型服务与火山引擎的真实线上联调仍需要用户自己的已开通账号。

## v0.3.0 悬浮球验证

- 设置默认关闭悬浮球，旧加密设置加载后使用 72 的安全默认直径。
- 实际创建透明 WPF 悬浮窗口并渲染：悬浮球 96×96、双气泡窗口 420×231。
- 窗口属性验证为 `Topmost=True`、`ShowActivated=False`、`ShowInTaskbar=False`。
- 主动状态为绿色空心麦克风和蓝色音量波浪；停止状态为红色麦克风及斜线。
- 输入气泡为绿色，输出气泡为白色，文字均为黑色；长文本受最大高度和滚动区域约束。
- 音量计算基准使用 3,200 字节 PCM16 帧，5,000 次测量的 p95 为 23.6 微秒，远低于每帧 1 毫秒预算。
- 流式回答只更新文本和合并后的滚动任务，不再为每个 token 重复切换窗口可见性或强制布局。

## v0.2.1 性能回归分析

脱敏诊断日志显示，同一环境中升级前 40 次请求的首字延迟中位数为 500 ms、P90 为 733 ms且没有超过 4.5 秒；升级后的 10 次请求中位数升至 3,897 ms、P90 为 7,128 ms，其中 5 次超过 4.5 秒。对应请求的本地检索仍约为 10–16 ms，因此瓶颈不在 RAG。

代码对比确认 v0.1 会向 DeepSeek V4 发送 `thinking: disabled`，而通用模型改造时移除了该提供商专用字段。DeepSeek V4 默认开启思考，应用又只展示正式 `content`，因此不可见推理直接推迟了首字。同时，v0.2 对独立问题也发送历史上下文，并可能让模型流处理与本地兜底竞争 UI 调度。

修复后：

- DeepSeek 官方端点及明确标记为 DeepSeek 的提供商恢复非思考、`temperature: 0.2` 的上一版请求合同。
- 其他 OpenAI 兼容提供商不接收 DeepSeek 专用字段。
- 历史上下文只在明显追问时携带最近 2 轮。
- 模型协调在后台执行，本地兜底先于模型任务启动，并提前到 4.0 秒。
- 确定性回归测试证明，即使模型枚举器同步阻塞 300 ms，本地兜底自身仍在 150 ms 测试预算内启动。

```powershell

```

v0.2.1 发布前检查结果为所有项目 0 个已知易受攻击包；v0.3.0 未新增或升级 NuGet 依赖。本次复查访问 NuGet 官方漏洞源时发生 60 秒网络超时，因此没有用失败的在线请求替代上一版已完成的检查结论。

- 密钥只进入 DPAPI `CurrentUser` 密文。
- 设置页不回显已保存凭据。
- 日志字段采用白名单，不记录问题、答案、知识正文、音频或密钥。
- DOCX 与 WebSocket 消息有大小上限。
- FTS/SQLite 查询参数化。
- BGE 模型和词表按固定提交下载并验证 SHA-256。

## 五秒目标

自动化测试证明：

- 云端首字先到时不显示本地兜底。
- 云端无首字时在配置的 4.0 秒边界显示知识库答案。
- 总请求 30 秒超时，新问题取消旧问题。

修复版没有擅自使用用户 API Key 发起计费请求，因此最终公网首字时间仍需用户在真实账号下复测。即使第三方服务变慢，只要知识库有命中，4.0 秒本地路径仍会先输出；网络完全不可用时则保留本地答案并显示安全错误。
