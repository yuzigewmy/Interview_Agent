# ADR-001：第一版供应商与检索架构

状态：已接受  
日期：2026-07-23

## 决策

第一版采用：

- DeepSeek V4 Flash 作为回答模型。
- 火山引擎大模型双向流式 ASR。
- 本地 BGE-small-zh-v1.5 ONNX 作为中文语义向量。
- SQLite FTS5 + 稠密向量 + 精确问题匹配，经 RRF 融合。
- 本地字符 n-gram 向量作为无模型或模型异常时的降级路径。

## 原因

主要指标是准确率和首字速度。文档体量只有约 241 个知识块，不需要部署独立向量数据库：

- SQLite 全量载入和余弦计算在此规模下简单、可控。
- FTS5 对技术名词、类名和关键字召回稳定。
- BGE 改善中文同义表达的语义召回。
- RRF 不依赖不同评分体系的绝对分数，易于组合精确、关键词和语义排名。
- 本地检索避免在回答关键路径上增加一个云向量服务往返。

## 延迟策略

DeepSeek 请求和 4.5 秒计时器并行。云端首字先到则不触发兜底；否则先展示本地命中，再继续等待流式云端回答。新问题通过问题级取消令牌终止旧请求。

## 安全边界

- DOCX、ASR 文本和知识片段均视为不可信输入。
- 知识片段被明确包裹为参考资料，不能覆盖系统角色。
- SQL 与 FTS 查询参数化，DOCX 文件大小、段落数和文本长度有上限。
- 密钥使用 Windows DPAPI CurrentUser 加密，不写日志。
- 外部服务只接收完成任务必需的数据。

## 后果

- 当前仅支持 Windows 10/11。
- 首次 BGE 建库比哈希向量慢，但只在导入时发生。
- 更换嵌入模型后必须重新导入 DOCX。
- 真实 DeepSeek/火山端到端联调需要用户自己的已开通账号。
